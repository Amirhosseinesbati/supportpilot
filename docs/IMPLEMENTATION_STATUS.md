## Known implementation limits to resolve

- Message SSE emits `message`, `answer_chunk`, and `final` events after a completed graph answer; the chunks are not model tokens during inference. Ingestion SSE also exists. First-token model latency remains unmeasured.
- The installed admin creates customer logins, products, and local orders through REST APIs. With Shopify selected, the read-only connector mirrors verified USD orders; a new SKU stays `unclassified` and blocks return eligibility until admin `PATCH /api/admin/products/{id}` sets a specific category. More than 100 lines or fulfillments fail closed until pagination is added. Local order creation is disabled when Shopify is the commerce source.
- The chat flow parses an ISO `as_of` date for policy-date questions and accepts an explicit evaluation `as_of`; the source endpoint can reopen published historical passages with effective dates. Manual support review for date-sensitive claims remains pending.
- The evaluation API reads the recorded model-run file when present and falls back to fixture validation. The UI must keep fixture integrity distinct from model quality; do not present a fixture pass as answer performance.
- Escalation saves a local ticket with server-verified order context and then synchronizes through the local or Zendesk support adapter, using a five-minute ledger claim lease and external ID reconciliation. The live Zendesk path has not been tested with credentials; a configured status indicator is not a live health check. Operator replies and resolution remain local.
- CONNECTED composition is bounded to one model call (`max_retries=0`), 25 seconds, default 700 output tokens, at most 16,000 characters in the human message, 4,000 question characters, 3,000 scoped-order characters, 8,000 evidence characters, and 1,000 per passage. `model_usage` stores provider token counts when supplied as known/partial/unknown without source text. Per-run **dollar** enforcement, a retention schedule and full erasure, redacted trace controls, CSRF/rate limiting, full OpenAPI response-type validation/generated client, and hardened deployment configuration remain pending.
